# SketchUp 객체 편집과 IFC 출력 (#14)

IFC는 SketchUp용 주 출력이고 DXF는 보조 출력이다. Plan과 팀 3D 메시를 유지하며
벽별 IfcWall, 문·창별 IfcDoor/IfcWindow와 개구부를 출력한다. API 연결은 #38이다.

## 사용 절차

1. IFC를 가져와 Site > Building > Level 0 안에서 객체를 선택한다.
2. 가져온 IFC는 그룹이 Site > Building > Level 0 아래 중첩돼 있다. 바로 선택하기
   쉽게 하려면 SketchUp에서 바깥 공간 그룹을 해제하고 벽·문·창 그룹만 남긴다.
3. 편집 SKP에서 벽·문·창을 직접 선택하고 이동한다. 면을 수정할 때는 해당 벽을
   더블클릭해 Push/Pull한다. 같은 편집 상태에서 Undo·Redo를 확인한다.
4. SKP를 저장하고 다시 연다. IFC 재출력은 원시 파일과 원본 ID를 복원한
   usable IFC를 구분한다. 원본 공간 계층은 원본 IFC에 보관한다.

DXF는 mm로 가져온 뒤 바깥 컴포넌트를 한 번 분해해 객체에 접근한다.
태그는 A-WALL·A-DOOR·A-WINDOW다. 문·창은 2D 윤곽이고 개구부가 있는 벽은
면이 분할돼 닫힌 솔리드가 아닐 수 있다. 팀 DXF 형상은 그대로 사용한다.

## 빈 DXF 개구부 블록 (#23)

2026-11-12, Windows SketchUp **27.0.267**의 Ruby SDK `Model#import`로
코드 생성 합성 DXF 4건을 가져왔고 모두 완료됐다. 문·창 각 하나가 있는 6 m 벽에서
빈 블록은 개구부 중심을 벽 끝 바깥에 둬 절단 구간이 없게 만들었다.

- 정상 문 + 정상 창: WALL_w1·DOOR_d1·WINDOW_g1, 3객체.
- 빈 문 + 정상 창: 빈 DOOR_d1 생략, WALL_w1·WINDOW_g1, 2객체.
- 정상 문 + 빈 창: 빈 WINDOW_g1 생략, WALL_w1·DOOR_d1, 2객체.
- 빈 문 + 빈 창: 두 개구부 생략, WALL_w1, 1객체.

원본 DXF의 블록/INSERT 12개 중 빈 문·창 4개만 생략됐고 전체 가져오기는
실패하지 않았다. **기존 처리 정책을 유지한다.** 절단 구간이 비어도 ID 보존을 위해
블록과 INSERT를 DXF에 남긴다. 원래 폭의 표시용 선이나 대체 객체를 추가하지 않는다.
DXF에 ID가 있어도 SketchUp에서 그 ID의 객체를 선택할 수 있다는 뜻은 아니다.
빈 블록 생략을 인식 누락이나 3D 기하 생성 오류로 판단하지 않는다.

컨테이너를 한 번 분해한 뒤 8객체의 독립 300 mm 이동·다른 객체 불변·복구를
확인했다. 벽 4개의 168면은 DXF 삼각형과 중심점·면적 기준으로 일대일 대응했고
mm 범위·태그·정상 문창의 2D 윤곽(각 0면·4모서리)도 유지됐다.
판정은 비유한 수치·다른 실행의 보고서·미분류 추가 객체를 실패로 처리하며, 실행마다
입력·설정·스크립트 SHA와 run ID를 기록해 대조했다.

이 결과는 **SDK/자동 검증**이며 실제 UI 클릭·SketchUp 2025·타 CAD 검증은 아니다.
경고 대화상자 유무는 별도 계측하지 않았다. 접합부 내부 빈 구간·부분 잘림·수치
찌꺼기 등 모든 원인을 이 4건으로 포괄하지 않는다. native 면 대조는 모든 정점·위상의
동치 증명이 아니며, 중심점/외곽 0.05 mm와 면적 max(0.5 mm², 원본의 0.0001)를 썼다.

검증은 PR40의 889a14d 기준이며, DXF 출력에 쓰는 `app/export/dxf.py`·
`app/geometry/walls.py`·`app/geometry/junctions.py`·`app/schemas/plan.py`는
PR40 머지 후 develop(dbcf194)에서도 같다. 합성 DXF·검증 도구·원시 보고서는 커밋하지 않았다.

## 검증 범위

- SketchUp 2027에서 합성 모델과 GT 유래 실제 도면 두 장의 객체 편집·복구,
  저장·재열기·IFC 재가져오기를 검사했다.
- 편집용 배치 129개 객체의 최상위 솔리드·형상·속성·재열기·재가져오기를 확인했다.
- 별도 PC SketchUp 2025에서 합성 모델의 선택·이동·치수 수정·SKP 재열기·IFC
  재출력을 확인했고 반환 IFC의 이름·분류·GlobalId·형상을 독립 비교했다.
- 별도 PC의 2025 확인에서 일부 Undo 항목과 공간 그룹을 해제한 SKP의 직접 사용성은
  아직 확인하지 못했다.
- 실제 도면은 GT 기반 후처리 검증이며 seg 추론 정확도 근거로 사용하지 않는다.

## 교환 한계

SketchUp IFC 재출력은 공간 트리를 추가하거나 void 관계를 제거할 수 있다.
편집용 SKP의 공간 그룹 해제 후 원시 IFC GlobalId가 재생성될 수 있어,
최종 교환 파일은 원본 이름·분류를 일대일 대응해 ID를 복원하고 형상을 검사한다.
문 이동 시 벽 개구부는 자동으로 따라가지 않는다.
2025에서 돌려받은 IFC에는 시험 이동·추가 도형·공간 계층 변경이 섞여 있어 형상 비교에는 쓰되 원본 대체용으로는 쓰지 않는다.

원본·파생 도면·모델·캡처는 커밋하지 않고 집계·SHA만 공개한다.


## 제공 범위

팀 서버에는 데스크톱 SketchUp 실행이나 SKP 변환을 연결하지 않는다. SKP는 사람이
SketchUp에서 저장하는 결과물이다. 이 PR은 exporter만 추가하고 write_outputs와
다운로드 API는 바꾸지 않는다. API 연결은 #38 계약 PR에서 이 PR 머지 후 다룬다.
SketchUp 2025 기준 확인 항목 중 미확인은 #14에 댓글로 남긴다.
