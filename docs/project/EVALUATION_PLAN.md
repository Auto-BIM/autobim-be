## 3. 시스템 지표 (② — #6)

같은 이미지를 **정답 마스크로 한 번, 예측 마스크로 한 번** 인식한다(replay 어댑터, 평가 팩). 두 결과를 같은 정답과 비교한다.

| 지표 | 정의 |
|---|---|
| 작업 성공률 | `succeeded` / 전체 |
| Plan 렌더 벽 IoU | Plan 벽을 픽셀로 다시 그린다(역변환 `x_px = x_mm/s`, `y_px = H − y_mm/s`, 두께만큼, **개구부 구간은 빼고**). 정답 벽 마스크와 IoU. ignore 영역은 제외 |
| 벽 총길이 오차 | `|L_plan − L_gt| / L_gt`. `L_plan` = 벽 중심선 길이 합 − 개구부 폭 합(px), `L_gt` = 정답 벽 마스크 골격 길이(px) |
| 개구부 P/R/F1 | 정답 = 평가 팩 `gt/<id>.json`의 문·창 박스. 예측 = Plan 개구부를 px로 되돌린 중심점·폭. 같은 종류이고 중심 거리 ≤ max(0.5 × 정답 박스 긴 변, 2 × t_med)이면 매칭(거리 순 탐욕) |
| 개구부 위치·폭 오차 | 매칭된 쌍의 벽 방향 중심 차, 폭 차(px. 축척이 정답에 있으면 mm) |
| 확인 필요 항목 수 | 이미지당 평균, 이유별 |

**오차 분해**

| 결과 | 뜻 |
|---|---|
| 정답 마스크 → Plan vs 정답 | **후처리 한계** (모델이 완벽해도 남는 오차) |
| 예측 마스크 → Plan vs 정답 | **시스템 전체 오차** |
| 둘의 차이 | **모델 기여 오차** |

**보고 표 2 (시스템, APT100 final 팩)**

| 입력 마스크 | 성공률 | 렌더 벽 IoU | 벽 길이 오차 | 문 F1 | 창 F1 | 위치 오차(중앙값) | 폭 오차(중앙값) |
|---|---|---|---|---|---|---|---|
| 정답 마스크 | | | | | | | |

## 5. 출력 유효성 (④)

| 검사 | 방법 | 합격 |
|---|---|---|
| glb | 프론트 뷰어에서 열림, 노드 수 = 벽 수 | 데모 세트 전부 |
| dxf 구조 | `ezdxf` `audit()` 오류 0, `WALL_`·`DOOR_`·`WINDOW_` 블록 수 = 벽 수 + 개구부 수, `$INSUNITS = 4` | 자동 테스트 |
| SketchUp | #14 (BE-N5) 체크리스트(벽 컴포넌트, 태그 3개, 면, 구멍, 크기) | 팀이 정한 버전에서 |

## 6. 정성 평가와 데모 세트 (⑤)

- 후보 10장(출처는 O-07)을 W12까지 고르고, 장마다 아래를 체크한다. G3 기준은 **8장 이상 합격**.
- 체크: 외곽 벽이 닫혀 있다 / 주요 내벽이 있다 / 문·창이 맞는 벽에 있다 / 축척이 그럴듯하다(현관문 폭 800~1000 mm 범위) / 3D와 dxf가 열린다.
- 합격한 도면 중 3~5장을 시연용으로 쓰고 결과를 미리 만들어 둔다(DEMO_PLAN).
